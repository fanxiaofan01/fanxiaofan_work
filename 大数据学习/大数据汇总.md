#### 空值的特性

空值和任何值进行算术运算得到的结果都为空；

```sql
SELECT NULL*100 FROM EMP;
SELECT COMM FROM EMP;
SELECT COMM,COMM+1000 FROM EMP;
SELECT COMM,COMM+1000 FROM EMP;
```

1.空值的转换
`NVL`(字段，字段里面的空值转换成值)
`NVL(COMM,0)`

```sql
SELECT COMM,NVL(COMM,0)+1000 FROM EMP;--空值转换为0.切都加上1000；
SELECT COMM,NVL(COMM,0)+1000 FROM EMP;
SELECT COMM,NVL(COMM,1000)+1000 FROM EMP;--空值转换为1000
```

2.有空值的任何列，进行关系运算得到的结果都不成立；

```sql
SELECT * FROM EMP WHERE COMM=0;--奖金=0共计一条数据
SELECT * FROM EMP WHERE COMM !=0;--奖金不等于0共计四条数据，空值不参与运算；
SELECT * FROM EMP WHERE COMM=0;
SELECT * FROM EMP WHERE COMM,NVL(COMM,0);

/*因为comm存在空值，导致关系运算不成立*/
```

3.空值不参与任何的聚合运算--带空值计算结果肯定是空值

```sql
SUM--求和函数
SELECT * FROM EMP;
SELECT COMM FROM EMP;
SELECT SUM(COMM) FROM EMP;--求和为2200，是因为空值不参与聚合运算；
```

4.空值在排序时候永远排在最大
--`ORDER BY` 可以排序 `DEST`是降序；

--练习实验

## oracle 常用数据类型

### char(长度)

--字符型CHAR CHAR  CHAR  
存储固定长度的字符串，长度可以自己设定，如果插入数据的长度小于设定的长度，用空格填充

### varchar2(长度)

--字符型VARCHAR2 VARCHAR2
存储的是可变长度的字符串，插入数据的时候只要不超过最大长度，就不会报错，也不会填充空格
默认长度是1，最大长度不能超过4000；

### number(P,S)

--数值型NUMBER
既可以存浮点数，也可以存整数，P代表最大的位数（如果有小数的话，那就包含整数和小数部分，P的默认长度是38
S代表小数的位数，整数位不能够超过P-S,fouze 否则会报错，小数位如果超过S，会自动进行四舍五入）

### date

--不需要给长度
存储的是日期时间，存储四位年，两位月，两位日，时分秒
布尔值类型：可以存TURE（真） FALSE(假)，通常被存为1（真），0（假）--了解

##### IN 和 EXISTS 

**IN**

> IN:WHERE 字段名 IN(子查询/多个值)
> 用于检查一个值是否存在子查询返回的结果中，它是比较左侧的表达式和子查询的结果，并返回匹配的行
>
> ```sql
> SELECT * FROM EMP WHERE DEPTNO IN(10,20,30);
> ```

**EXISTS**
WHERE EXISTS (子查询)
①第一种情况：<span style="color:#FF0000;">子查询能单独执行，有结果就返回主表的所有数据，没结果就返回空；</span>

```sql
SELECT * FROM EMP WHERE EXISTS(SELECT 1 FROM DUAL where 1=1);
/*(SELECT 1 FROM DUAL where 1=1)能单独执行，并返回结果，所以这条语句返回的是SELECT * FROM EMP 的所有结果*/
SELECT * FROM EMP WHERE EXISTS(SELECT * FROM EMP WHERE DEPTNO IN(10,20,30));
/*(SELECT * FROM EMP WHERE DEPTNO IN(10,20,30)能单独执行，并返回结果，所以这条语句返回的是SELECT * FROM EMP 的所有结果*/
SELECT * FROM EMP WHERE EXISTS(SELECT 1 FROM DUAL where 1=0);
/*(SELECT 1 FROM DUAL where 1=0)能单独执行，但是没返回结果，所以这条语句返回的是空*/
```

②第二种情况：<span style="color:#FF0000;">子查询不能单独执行，需要借助外部查询的字段，那就是返回外部查询和内部查询的交集，相当内关联，但是只返回主表的数据</span>

```sql
SELECT * FROM EMP E WHERE EXISTS(SELECT * FROM EMP E1 WHERE E.DEPTNO=10);
/*(SELECT * FROM EMP E1 WHERE E.DEPTNO=10)不能单独执行，所以返回的是交集，而且只返回主表的数据*/

<span style="color:#0000FF;">IN 和 EXISTS 的区别</span>

> IN: 用于检查一个值是否存在于子查询返回的结果中，它将比较左侧的表达式与子查询的结果，并返回匹配的行，<span style="color:#FF0000;">如果子查询返回的结果集中包含与左侧表达式匹配的值，则条件为真</span>
>
> EXISTS:用于检查子查询是否返回了至少一行数据，他只关心子查询是否返回结果，而不关心具体的值是什么，<span style="color:#FF0000;">如果子查询返回了至少一行结果，则条件为真</span>

<span style="color:#0000FF;">IN 和 EXISTS 谁的效率高</span>

> <span style="color:#FF00FF;">主表为大表，子表为小表，IN的效率更高，主表为小表，子表为大表是，EXISTS的效率更高</span>

NOT EXISTS 

--主查询的数据在子查询中不存在的部分

```sql
SELECT * FROM DEPT E WHERE EXISTS(SELECT * FROM EMP E1 WHERE E1.DEPTNO=E.DEPTNO);--10,20,30
SELECT * FROM DEPT E WHERE NOT EXISTS(SELECT * FROM EMP E1 WHERE E1.DEPTNO=E.DEPTNO);--40
--主表有(10,20,30,40)，相交部分(10,20,30),NOT EXISTS等于主表数据减去相交的部分，所以返回40
SELECT * FROM EMP E WHERE EXISTS(SELECT * FROM DEPT E1 WHERE E1.DEPTNO=E.DEPTNO);--10,20,30主表全部数据
SELECT * FROM EMP E WHERE NOT EXISTS(SELECT * FROM DEPT E1 WHERE E1.DEPTNO=E.DEPTNO);
--主表有(10,20,30)，相交部分(10,20,30),NOT EXISTS等于主表数据减去相交的部分，所以返回空

##### 临时表

WITH AS  临时表
/*使用SQL 优化的一种方法，将子查询用临时表封装起来，先把子查询
子查询查询的结果算出来，放在临时缓存空间*/
如果查询的结果集被放到临时表中空间，数据量太大的话（几千万），可能会爆内存不足的错误
语法：
WITH 临时表1 AS （查询语句1），--一个临时表写完，也用都好隔开
     临时表2 AS （查询语句2），--第二个临时表不需要用WITH开头
     临时表n AS （查询语句n）--最后一个临时表不需要逗号
     SELECT * FROM 临时表1；

WITH EMP10 AS （SELECT * FROM EMP WHERE DEPTNO=10），--一个临时表写完，也用都好隔开
     EMP20 AS （SELECT * FROM EMP WHERE DEPTNO=20），--第二个临时表不需要用WITH开头

4.3.2.3 IN 和 EXISTS
IN:WHERE  字段名 IN(子查询/多个值)
用于检查一个值是否存在子查询反馈的结果中，它是比较左侧的表达式和子查询的结果
并返回匹配的行
SELECT * FROM EMP WHERE DEPTNO IN(10,20,30);
--EXISTS
WHERE EXISTS (子查询) 
第一种情况：子查询能单独执行，有结果就返回主表的所有结果，没结果就返回空
SELECT * FROM EMP WHERE EXISTS(SELECT 1 FROM DUAL WHERE 1=1);
SELECT * FROM EMP WHERE EXISTS(SELECT 1 FROM DUAL WHERE 1=0);
SELECT * FROM EMP WHERE EXISTS(SELECT * FROM EMP WHERE DEPTNO=10);


第二种情况：子查询不能够单独执行，需要借助外部查询的字段，那就是返回外部查询
和内部查询的交集，相当于内关联，但是只返回主表的数据；
SELECT * FROM EMP E WHERE EXISTS(SELECT * FROM EMP E1 WHERE E.DEPTNO=10);--内部不能够单独执行，相当于内关联，返回交集，且只返回主表的数据，不返回附表数据
SELECT * FROM EMP E WHERE EXISTS(SELECT * FROM EMP E1 WHERE E1.DEPTNO=10);--内部能够单独执行，返回主表的所有数据
SELECT * FROM EMP E WHERE EXISTS(SELECT * FROM EMP E1 WHERE E.DEPTNO=E1.DEPTNO);
SELECT * FROM DEPT E WHERE EXISTS(SELECT * FROM EMP E1 WHERE E.DEPTNO=E1.DEPTNO);

IN 和 EXISTS 的区别
IN : 用于检查一个值是否存在于子查询范围的结果中，它将比较左侧的表达式与
查询的结果并返回匹配的行，如果子查询返回的结果集中包含与左侧表达式匹配的值
则条件为真；
EXISTS 用于检查子查询是否返回了至少一行数据，他只关心子查询是否返回结果
而不关心具体的值是什么，如果子查询返回了至少一行结果，则条件为真；

IN 和 EXISTS 谁的效率更高？
主表为大表的时候，子表为小表的时候，IN 的效率更高，
主表为小表的时候，子表为大表的时候，EXISTS 的效率更高，

NOT EXISTS --主查询中数据在子查询中不存在的部分
SELECT * FROM EMP E WHERE NOT EXISTS(SELECT * FROM EMP E1 WHERE E.DEPTNO=E1.DEPTNO);--主表数据与子表数据都有相交，显示空值
SELECT * FROM DEPT E WHERE EXISTS(SELECT * FROM EMP E1 WHERE E.DEPTNO=E1.DEPTNO);--返回主表与子表相交部分数据，10,20,30
SELECT * FROM DEPT E WHERE NOT EXISTS(SELECT * FROM EMP E1 WHERE E.DEPTNO=E1.DEPTNO);--主表与子表数据不相交部分，返回主表剩余部分数据，就40部门

用分析函数和聚合函数搭配 GROUP BY 的区别
1.聚合函数搭配 GROUP BY 的时候，SELECT 后面的字段有限制，只能跟聚合函数表达式
或者 GROUP BY 后面的字段，但是分析（开窗）弥补了这一点，想查那个字段就可以查哪个字段
2.聚合函数用 GROUP BY 分组，开窗函数用 PARTITION BY 分组
3.聚合函数每一组只返回一个值，分析函数每行都会返回一个值
4.聚合函数可以作为筛选条件（HAVING），分析函数不能--执行顺序

--*************************************
DELETE 和 TRUNCATE 的区别;
DELETE 和 TRUNCATE 都是删除数据

> 1. TRUNCATE 是 DDL 命令，删除的数据不能恢复，DELETE 是 DML 命令，删除之后可以回滚
>    可以通过日志文件恢复；
> 2. TRUNCATE 比 DELETE 速度快，因为 TRUNCATE 是直接 DROP 表。然后重新创建一个表框架
>    DELETE 是一条一条的删除；
> 3. TRUNCATE 删除的数据不能恢复，比较危险，工作中慎用
>

## 视图

### 视图的概念

 **视图（view）**类似一个虚表，是建立在一张或多张基表之上的预定义查询（类似子查询）。视图的定义语句会存储在数据字典中，查询这个视图内容的时候，视图对应的SQL会再执行一次，然后把结果返回。

视图的优点：

1.可以限制用户只能通过视图检索数据，这样就可以对最终用户屏蔽建表时底层的基表，具有安全性。
2.可以将复杂的查询保存为视图，屏蔽复杂性。

3.简化代码开发：可以将复杂的查询操作定义成视图，在代码使用简单的查询视图代替复杂的表关联查询；

4.保密：某些表内的**隐私字段**或**敏感字段**，如果不希望使用者看见，就可以把使用者需要使用的字段创建一个视图。这样使用者就  不知道**基表**，以及基表的**表结构**

5.简化权限：不用对于不同用户去授予表字段权限，而是直接建视图，将**视图的权限**给对应**用户**就可以。

<font color='red'>视图与表的区别:</font>

​    1.视图不占用物理空间（物化视图除外），而表是占用物理空间的。

​    2.表是内容，而视图是预定义的虚的表结构。

​    3.视图的建立和删除只影响自身而不影响表。

### 创建视图

语法格式：

```sql
CREATE [OR REPLACE] [FORCE|NOFORCE] VIEW VIEW_NAME
AS
SELECT 语句
[WITH READ ONLY]
```

关键字解读：

1.OR REPLACE：如果视图已经存在，则替换旧视图；
2.FORCE：即使基表不存在，也可以创建视图，但该视图不能正常使用，当基表创建成功后，视图才能正常使用。
3.NOFORCE：如果基表不存在，无法创建视图，该项是默认选项。
4.WITH READ ONLY：说明视图是只读视图，不能通过该视图进行增删改操作

默认可以通过视图对基表执行增删改操作，但是通常不是用对基表进行DML操作。现实开发中，基本上不通过视图对表中的数据进行增删改操作。

### 视图使用案例

```sql
create or replace view v_emp_info
as
select a.empno   as "员工编号"
      ,a.ename   as "员工名称"
      ,b.dname   as "归属部门"

```




### 拓展知识：物化视图

#### 介绍

物化视图是一种特殊的物理表，“物化”(Materialized)视图是相对普通视图而言的。普通视图是虚拟表，不占用物理空间；**物化视图在某种意义上说就是一个物理表，会占用物理空间**。

物化视图的类型：

物化视图有两种类型

1.ON DEMAND物化视图

2.ON COMMIT物化视图

3.物化视图创建语法

```sql
create materialized view 物化视图名         -- 1. 创建物化视图
build [immediate | deferred] 			  -- 2. 创建方式，默认 immediate
refresh [force | fast | complete | never] -- 3. 物化视图刷新方式，默认 force
on [commit | demand] 					  -- 4. 刷新触发方式
start with 开始时间						   -- 5. 设置开始时间
next 间隔时间				               -- 6. 设置间隔时间
with [primary key | rowid]                -- 7. 类型，默认 primary key
[enable | disable] query rewrite          -- 8. 是否启用查询重写
as	                                      -- 9. 关键字
select ...;                               -- 10. select 语句
```



### 物化视图使用案例：

#### 案例一、ON DEMAND物化视图

 <font color='red'>**ON DEMAND物化视图表示数据需要手动刷新**</font>

--1.创建基表(视图读取的表，也可以说是源表)

```sql
create table base_tab_1 as select t.* from scott.dept t;
```

--2.创建物化视图(2分钟刷新一次)

```sql
create materialized view mv_dept_demand 
refresh force on demand 
start with sysdate
next sysdate+2/1440
as select * from base_tab_1;
```

--3.插入数据,模拟基表数据有变化

```sql
insert into base_tab_1(deptno,
                       dname,
                       loc)
                  values(60,'abc123','hanz');
                  commit;
```

--4.确认数据已经插入基表                  

```sql
select rowid,t.* from base_tab_1 t;
```

--5.查询基表和物化视图，会发现deptno=60的数据还没有刷新进来，两分钟后再查询会发现数据已刷新进来                 

```sql
select t.* from mv_dept_demand t;
```



#### 案例二、ON COMMIT物化视图

<font color='red'>**ON COMMIT物化视图表示数据会自动刷新**</font>

--1.创建基表(视图读取的表，也可以说是源表)

```sql
create table base_tab_2 as select t.* from scott.dept t;
```

--2.为表base_tab_2创建物化视图日志并授权给查询用户(当前用户查询可以不用授权)

```sql
--基表必须要有主键约束
alter table base_tab_2 add constraint pk_deptno primary key (deptno);

--创建物化视图日志
create materialized view log on base_tab_2;

--如果物化视图建在当前用户下，查询物化视图可以不授权
grant select on MLOG$_base_tab_2 to 查询用户名;
```

--3.创建物化视图

```sql
create materialized view mv_dept_com
refresh force on commit
as select * from base_tab_2;
```

--4.插入数据,模拟基表数据有变化

```sql

                       dname,
                       loc)
                  values(70,'kkk','addddd');
                  commit;
```

--5.确认数据已经插入基表                  

```sql
select rowid,t.* from base_tab_2 t;
```

--6.查询基表和物化视图，会发现数据已刷新进来                 

```sql
select t.* from mv_dept_com t;

[SORTED BY (col_name [ASC|DESC], ...)] INTO num_buckets BUCKETS] [ROW FORMAT row_format] [STORED AS file_format] [LOCATION hdfs_path] [TBLPROPERTIES (property_name=property_value, ...)]

2）字段解释说明 

> （1）`CREATE TABLE` 创建一个指定名字的表。如果相同名字的表已经存在，则抛出异常；用户可以用 IF NOT EXISTS 选项来忽略这个异常。 
>
> （2）EXTERNAL 关键字可以让用户创建一个外部表，在建表的同时可以指定一个指向实际数据的路径（LOCATION），在删除表的时候，内部表的元数据和数据会被一起删除，而外部表只删除元数据，不删除数据。 
>
> （3）COMMENT：为表和列添加注释。 
>
> （4）PARTITIONED BY 创建分区表 
>
> （5）CLUSTERED BY 创建分桶表 
>
> （6）SORTED BY 不常用，对桶中的一个或多个列另外排序 
>
> （7）ROW FORMAT  
>
> ```hive
> DELIMITED [FIELDS TERMINATED BY char] [COLLECTION ITEMS TERMINATED BY char] 
> 
>   [MAP KEYS TERMINATED BY char] [LINES TERMINATED BY char] 
> 
>   | SERDE serde_name [WITH SERDEPROPERTIES (property_name=property_value, property_name=property_value, ...)] 
> ```
>
> 用户在建表的时候可以自定义 SerDe 或者使用自带的 SerDe。如果没有指定 ROW 
>
> FORMAT 或者 ROW FORMAT DELIMITED，将会使用自带的 SerDe。在建表的时候，用户还需要为表指定列，用户在指定表的列的同时也会指定自定义的 SerDe，Hive 通过 SerDe 确定表的具体的列的数据。 
>
> SerDe 是 Serialize/Deserilize 的简称， hive 使用 Serde 进行行对象的序列与反序列化。 
>
> （8）STORED AS 指定存储文件类型 常用的存储文件类型：`SEQUENCEFILE`（二进制序列文件）、`TEXTFILE`（文本）、`RCFILE`（列式存储格式文件） 
>
> 如果文件数据是纯文本，可以使用STORED AS TEXTFILE。如果数据需要压缩，使用 STORED AS SEQUENCEFILE。 
>
> （9）LOCATION ：指定表在 HDFS 上的存储位置。 
>
> （10）AS：后跟查询语句，根据查询结果创建表。 
>
> （11）LIKE 允许用户复制现有的表结构，但是不复制数据。
>

```hive

# sqoop数据抽取

## sqoop 概述

Apache sqoop 是在H**adoop 生态体系和 rdbms（关系型数据库）体系**之间传输数据的一种工具；

sqoop的核心设计思想是利用 MapReduce 加快数据传输速度。也就是说sqoop 的导入和导出功能是通过基于 map task 的MapReduce 作业实现的；所以它是一种批处理方式进行数据传输，难以实现实时的数据进行导入和导出。

Hadoop 生态系统包括：hdfs、hive、HBASE等

rdbms 体系包括：mysql、oracle、DB2等

![image-20241031172902251](C:\Users\EDY\AppData\Roaming\Typora\typora-user-images\image-20241031172902251.png)

站在Apache 立场看待数据流转问题，可以分为数据的导入导出：

> import：数据导入，rdbms→hadoop
>
> export：数据导出，hadoop→rdbms
>

**注意事项：**

1. 有了 `--query` ，就不要有   `--table，--where，--columns` 了，否则会报错；
2. 末尾必须加上 `'and $CONDITIONS;'`  因为 `sqoop` 要将 `SQL` 语句交给多个不同的 `maptask`  执行，每个 `maptask` 执行 `SQL` 时要按任务规划加范围条件，所以就提供了这个 $`CONDITIONS` 作为将来拼接条件的占位符；
3. 禁用聚合函数，这个SQL 不要过于复杂而且不允许使用聚合函数，因为会分区处理（除非 m=1）
4. 引导问题。如果有字符串要用到引号，就外层使用单引号，内层使用双引号，如果外层使用双引号会变成弱引用，里面的其他符号会具有特殊意义。除非使用转移符号 \。

### 命令解读

- `--check-column` (字段)

\#用来指定一些列，这些列在增量导入时用来检查这些数据是否作为增量数据进行导入，和关系型数据库中的自增字段及时间戳类似。

--append ##lastmodified模式的选项1，追加

--merge-key ##lastmodified模式的选项2，合并
